# Prodigi Direct for WooCommerce — design

Date: 2026-09-06. Status: approved in conversation (Jonas, 2026-09-06: "set things up in github and build it out").

## Why

Prodigi's WooCommerce connector needs every product variant mapped one at a time in the Prodigi dashboard (SKU, sizing, wrap). Prodigi support confirmed on 2026-09-06 there is no CSV or API for that. Tiffany Love Art has 146 variants across 11 paintings, more once framed prints are added. This plugin removes the mapping step: WooCommerce sends each paid order straight to Prodigi's v4 Orders API, and the mapping lives on the WooCommerce variations, generated from a catalogue the plugin carries.

## Who it is for

A non-technical artist running her own WooCommerce shop. She must never see a SKU. She works in paintings, materials, sizes, frame colours, and prices.

## What "done" looks like

1. Plugin installs from a GitHub release zip on a WordPress 6.6+ / WooCommerce 9+ site (tested on WP 7.1 / Woo 11.1 / PHP 8.5, her stack).
2. On a staging clone of her shop, a sandbox order placed at checkout reaches Prodigi's sandbox, the WooCommerce order shows Prodigi status and tracking, and the customer gets the tracking note.
3. Her 11 paintings' variations (paper, rolled canvas, gallery wrap) are generated by the plugin from the catalogue and match the existing prices, plus framed prints as new variations with costs shown.
4. Errors are plain language with a retry button; sandbox mode is unmistakable.
5. README + a step-by-step guide for Tiffany in `Projects with JH/shop/`, install and live-cutover instructions for Jonas, a draft note to Prodigi.
6. Live site untouched.

## Architecture

A single WordPress plugin, PHP 8.1+, no build step, no Composer dependencies at runtime.

```
prodigi-direct/
  prodigi-direct.php          bootstrap, constants, autoload, HPOS declaration
  includes/
    class-catalogue.php       loads catalogue/*.json; lookups (family → sizes → sku, attributes)
    class-api-client.php      Prodigi v4 HTTP client (wp_remote_*), sandbox/live base URL, quotes, products, orders
    class-assets.php          private artwork store + signed URL endpoint + DPI checks
    class-product-builder.php builds/updates variations for a product from the chosen families/sizes/frames
    class-pricing.php         cached quotes per SKU+attributes (transient, daily refresh); margin maths
    class-order-sender.php    order → Prodigi payload; Action Scheduler job; retries; order notes
    class-order-status.php    callback endpoint + polling fallback; status → order meta/notes/status
    class-catalogue-check.php weekly SKU/price drift check → admin notice + email
    admin/
      class-settings.php      Prodigi settings page (key, mode, shipping, test order, check catalogue)
      class-product-panel.php "Prodigi" product-data tab (artwork, families, sizes, frames, build)
      class-variation-fields.php per-variation SKU/attribute display + cost/margin
      class-orders-ui.php     Prodigi meta box on the order screen + column on the orders list
    cli/class-cli.php         wp prodigi-direct seed | check-catalogue | send <order>
  catalogue/
    prodigi.json              families, sizes, SKUs, attributes, print areas (verified 2026-09-06)
  assets/admin.css, admin.js
  tests/                      PHPUnit for the pure parts (catalogue, payload builder, signing, pricing)
  examples/tiffany-love-art-seed.csv  the 146-row seed (painting, family, size, price)
```

### Data model

- Product (variable): `_prodigi_artwork_id` (attachment id in the private store), `_prodigi_families` (array of family keys), `_prodigi_sizes` (array of size keys), `_prodigi_frames` (array of frame colours), `_prodigi_managed = yes`.
- Variation: `_prodigi_sku`, `_prodigi_attributes` (JSON: wrap/frame/mount…), `_prodigi_sizing` (fitPrintArea), `_prodigi_family`, `_prodigi_size`. WooCommerce attributes on the variation: `Size` (e.g. 16 x 20"), `Material` (Fine Art Paper / Rolled Canvas / Gallery Wrapped / Framed Print), `Frame` (Black / White / Natural; only for framed).
- Order: `_prodigi_order_id`, `_prodigi_status` (stage), `_prodigi_last_error`, `_prodigi_shipments` (JSON), `_prodigi_sent_at`, `_prodigi_mode` (sandbox/live).
- Options: `prodigi_direct_settings` {api_key_live, api_key_sandbox, mode, shipping_method, notify_email, auto_complete_on_ship}. Keys stored in the options table like every other WooCommerce payment/shipping plugin; never in files.

### Flows

**Build variations.** She picks artwork + families + sizes (+ frame colours) on the product's Prodigi tab and clicks Build. The builder creates missing variations with attributes and Prodigi meta, updates the meta on existing ones (matched by family+size+frame), never deletes (unticked ones are set to "disabled" in Woo, not removed), and leaves prices alone unless empty. New empty-price variations get the price from the seed CSV when one matches, else are flagged red in the list until she sets one. Sizes the artwork can't print at ≥ 150 DPI show a warning; below 100 DPI they're blocked.

**Cost and margin.** Pricing pulls a quote per SKU+attributes (US, Budget) once a day and caches it. Variation rows show "Prodigi cost $X incl. shipping · you keep $Y (Z%)". Negative margin turns the row red and blocks Build from enabling that variation until she confirms.

**Order.** On `woocommerce_payment_complete` (and `processing` status for manual payments), an Action Scheduler job builds the payload: recipient from the shipping address, one item per Prodigi-managed line (copies = qty, sku, sizing, attributes, asset = signed URL for the product's artwork, merchantReference = order id + line id), merchantReference = order number, callbackUrl = the plugin's REST endpoint, idempotency on order id. Non-Prodigi lines (originals) are ignored and noted. Success → order note "Sent to Prodigi (id …)", status meta. Failure → order note in plain words, `_prodigi_last_error`, admin notice + email, order flagged in the list; the meta box has Retry. Never sends twice: a lock meta + Prodigi's own idempotency.

**Status.** Prodigi calls back (or the plugin polls every 6 h for orders in flight if callbacks are absent). Stage → meta + note. On shipment → tracking saved, customer note with carrier + link, order marked Completed when all lines shipped (setting).

**Assets.** Artwork uploads go to `wp-content/uploads/prodigi-private/` (nginx `deny all`, `.htaccess` for Apache). Signed URL `/wp-json/prodigi-direct/v1/asset/{id}?exp=…&sig=HMAC(secret, id|exp)`; served with X-Accel-Redirect when nginx supports it, PHP stream otherwise. Links last 48 h (Prodigi fetches once on order creation). Existing masters in `/srv/art-master` can be imported by CLI without re-upload.

**Sandbox.** Mode switch on settings. In sandbox: a persistent orange admin bar badge "Prodigi SANDBOX — orders are not printed", the base URL switches, and a "Send test order" button on settings creates a real sandbox order for a chosen variation to a fixed test address.

**Catalogue upkeep.** `catalogue/prodigi.json` is the plugin's knowledge. A weekly cron (and a button) checks every SKU in use with GET products/{sku} and refreshes quotes; a retired SKU or a cost change > 10% raises an admin notice and an email to the notify address. New product families (a new frame type, a new paper) need a catalogue update: a JSON edit in the repo, which is the one thing that stays a developer job. The CLI `check-catalogue` prints the diff for that.

### Error vocabulary (what she sees)

- "Prodigi couldn't fetch the artwork for X" (asset 4xx)
- "Prodigi doesn't ship this product to {country}"
- "The shipping address was rejected: {reason}"
- "Prodigi's API is unavailable, will retry in 15 minutes (attempt 2 of 5)"
- "This variation has no Prodigi product behind it — open the product and press Build"

### Testing

- PHPUnit (no WordPress bootstrap) for: catalogue lookups, payload builder, signature, DPI maths, margin maths, status mapping. Written first.
- Local WordPress (brew php + mariadb + wp-cli) with WooCommerce, the plugin, and Prodigi sandbox for an end-to-end order.
- Staging clone of her real shop on her own server (staging.tiffanyloveart.com, noindex, Stripe test mode, Prodigi connector NOT connected) for the final run with her 11 products and real masters.

### Out of scope

Mockup images, non-Prodigi POD providers, multi-currency, Prodigi's product range beyond paper / canvas / framed, retail sync back to Prodigi's dashboard.
